# V1.5 capacity and responsibility-handover diagnostics

V1.5 retains V0 and V1 unchanged and layers diagnostics and an optional rule controller over V1. Stage A uses target-aware scheduling with target in {3,4} and charger capacity in {1,2}. Stage B compares naive, target-aware, and target-aware plus uncertainty-waypoint handover at target 4/capacity 1. All use six slots, full 360 kJ initial batteries, 600 W, 0.9 efficiency and unmodified pretrained actors; no smoke charging overrides or training are used.

The original V1 formal runner used the environment's default corner initial positions. This protocol instead requires a shared existing GA initial deployment: all V1.5 runs use the fixed four-position `best.deployment_positions` in `Our_experiment/GA/data/ga_best_deployment_random10_w23_g10_i999999_pool0_200.json`. It is not reoptimized per method, seed or wind. This means V1.5 A3 has V1's target/capacity/charging settings but a different starting deployment; old V1 CSVs are not pooled or treated as exact reruns. The vehicle remains at (10,10), independent of GA destinations and GBS.

For a newly assigned outgoing/replacement pair, the policy partitions the 20×20 map by Chebyshev distance to currently active UAVs, with lowest ID breaking ties. Candidate cells have uncertainty >0, are unoccupied and differ from the vehicle. Outgoing-region cells are ranked by `uncertainty + 0.5*nearest_other_active_distance/19 - 0.25*distance_from_vehicle/19`, then uncertainty, separation, travel distance, x and y. If no region candidate exists, the same scoring is used globally and a fallback event is emitted; if no valid cell exists no waypoint is created.

An active replacement moves by the legal eight-neighbor action minimizing `distance_to_target/19 + 0.2*flight_energy/max_neighbor_flight_energy + 2*occupied`, breaking ties by original direction order. It searches and offloads as usual. This cost intentionally can select a sideways move to save energy or avoid an occupied cell; it does not prove monotonically decreasing distance. The waypoint closes on arrival, external resolution, 30 executed waypoint steps, return, or episode end. Every move and release is recorded. The V1 scheduler's one-to-one binding and the separate single-waypoint guard are retained; `none` does not change the V1 action sequence.

For each run we retain per-slot trajectory, fixed-slot energy/status, visit maps, fleet/offload/handover timelines and all events. `total_active_uav_steps` is the number of UAV-steps actually eligible to search; a just-launched UAV first searches on the next step. Coverage gain per active UAV-step uses newly covered cells divided by this count. Repeats include blocked/stationary eligible visits and previously cleared cells. Jaccard averages over pairs with nonempty union. Proximity counts active pairs at Chebyshev distance ≤1 per step. The full same-cell attempt count is unavailable because simultaneous intended destinations are not retained. The separately named `sequential_blocked_move_attempts` records only attempted moves blocked by an occupied active position. Same-target contention uses requested target counts, including local processing, and is a proxy, not a network congestion rate.

V1 does not maintain simultaneous persistent regions for all active handovers, and it does not model dropped tasks: `simultaneous_same_region_count` and `failed_or_dropped_task_count` are explicitly unavailable (null), not inferred zeros. Waiting and replacement delays are observed completions, not estimates of right-censored waits. Handover flight energy is recorded but is not the incremental energy cost versus a matched non-handover path.

Both stages use the same wind seeds 11,23,4800 and evaluation seeds 42–51, with terrain/infrastructure/trajectory seeded identically within each paired condition. Per-run code/weights/data fingerprint and configuration are recorded. Comparisons are descriptive first-minus-second paired differences; no statistical significance or real hardware implications are claimed.
