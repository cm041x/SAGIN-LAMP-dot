# Dynamic HCSAC baseline specification

This is a baseline implementation, not a learned fleet scheduler. Zero-shot uses the original actor checkpoints; scratch starts the original CNN and GCN architectures with random actor/critic weights and alpha 0.01; finetune loads actor, both critics, both target critics and log alpha strictly from the original checkpoints, with fresh optimizers and empty replay. The original SAC and all V0/V1/V1.5 environment code and weights remain unchanged.

All methods use V1.5 target-aware scheduling, no waypoint, six slots, 4 initial active, target 4, one 600 W charger at efficiency 0.9, minimum launch charge 95%, full 360 kJ batteries and the fixed GA deployment from the V1.5 experiment. No fleet or charge reward, extra state, additional network feature, or GA optimization is introduced. CNN uses the original 3×15×15 input, 128-hidden actor and critics with 8 actions; GCN uses six node features, 128 hidden units and five actions.

The CNN replay stores only slots in `env.eligible` after flight; transition witnesses record active-before and executed slot IDs. Newly launched and non-executed slots are excluded. GCN replay stores CPU-cloned graphs and six-slot actions, rewards, current/next masks and terminal indicators. Batched graph outputs are explicitly remapped using `batch`, `node_type` and `slot_id`; actor, double critic and alpha losses reduce over current eligible slots, while bootstrapping requires next-active and nonterminal. Empty masks skip the update. The discrete SAC objective and negative target entropy convention match the original implementation.

Training wind classes are balanced and exclude all validation and test wind seeds. Nine deterministic validation combinations are sampled from the catalog; test winds are 11,23,4800 with terrain/infrastructure seeds 42–51. Each training seed generates a shared episode manifest for scratch and finetune. Validation selects by mean coverage AUC, then coverage, lower repeat ratio and lower energy; test data are not used for model selection. The requested pilot test-condition rollout is a pipeline check and is not used for tuning.

Checkpoints atomically save both agents, optimizers, log temperatures, both replay buffers, episode/step, best validation, manifest digest and Python/NumPy/Torch RNG. Resume restores these values at an episode boundary and checks the episode-manifest prefix and training code fingerprint. The environment-step horizon is 500; formal hyperparameters are 1000 episodes per run, batch 128, warmup 2000 steps, one update per branch per step, and validation each 50 episodes. Model selection and comparisons must be reported across all three training seeds; mode-level comparisons first average seeds within each environment condition. CPU estimates do not establish that formal training has completed.
