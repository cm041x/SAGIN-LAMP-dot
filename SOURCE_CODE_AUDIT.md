# Source code audit

The cited files refer to the original copied implementation, not claims about a paper.

- `ENV/UAVenv_SAC_Original.py`: `N` sizes UAV dictionaries, arrays and loops. Each UAV stores position, destination, energy, done, offload and link. Its eight directions use the sampled wind and a power model of `0.5*M*speed² + P_hover` for a fixed `T`. The original `step` updates movement/search then may mark done and directly place the UAV at its destination; `step_offload` applies service contention/energy and has the same terminal shortcut. The original approximate `return_energy_with_wind` also includes a destination hover estimate. The new environment instead sums the actual adjacent-cell route and does not claim identical return timing.
- `generate_sagin_graph` inserts UAV nodes first, then GBS, HAPS, LEO, Cloud; `get_obs_2` updates links and converts NetworkX to PyG. `PolicyNet_GCN` outputs nodes selected by `node_type == 0`, making insertion order relevant. Dynamic slots are retained and `slot_id` makes this mapping explicit. The CNN is shared per UAV, takes a 3×15×15 observation, and does not encode fleet size in its weights. The GCN similarly has six input features and emits one action distribution per UAV node. The 4-to-6 compatibility was tested, not assumed.
- `UAV_VIS_offloading_2.py` executes flight before graph/offload. Its visualization allocates trajectories and visit counts per `env.N` and treats the first `done` as lifetime; this is not a suitable status/lifetime definition for repeated rotation. Its replay entry point passes `position_starts` and `position_ends` to `reset`, along with precomputed trajectory/offload actions. The V0 runner does not change or optimize GA outputs.
- `vis_offloading_seed_executor.py` constructs both SAC agents with 128 hidden units, loads actor and critic checkpoints via `UAV_SAVE.py`, and supplies independently configurable wind, terrain, trajectory and infrastructure seeds. V0 loads the same saved actor dictionaries directly for inference; it neither reloads optimizers nor trains. The original default `take_action` samples a categorical distribution; V0 diagnostics use deterministic argmax.
- Original state and checkpoint tests before and after implementation are recorded by `baseline_check.py` and `baseline_check.json`. Refer to `HCSAC_FILES_GUIDE.md` and `HCSAC_compare_metrics_by_wind.py` for the original batch metrics/visualization paths; their published metrics are not reused as V0 validation.
